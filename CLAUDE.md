# Руководство для Claude по OpenFang

Этот файл содержит специфические для проекта инструкции по разработке OpenFang с использованием Claude или подобных ИИ-ассистентов.

## Стек технологий
- **Язык**: Rust (версия 1.75+)
- **Конфигурация**: TOML
- **БД/Память**: SQLite (через `rusqlite`), векторные эмбеддинги
- **Инструментарий**: Cargo, Clippy, rustfmt
- **API**: REST, WebSocket, SSE (через `axum`)
- **UI**: Alpine.js (SPA дашборд), Tauri (десктоп)

## Правила кодирования
- **Никаких `unwrap()`**: Всегда используйте обработку ошибок через `Result` и оператор `?`. Для типов ошибок используйте `thiserror`.
- **Документация**: Все публичные функции и типы должны иметь комментарии `///`.
- **Тесты**: Каждая новая функция должна сопровождаться юнит-тестами. Новые эндпоинты API требуют живых интеграционных тестов (см. `AGENTS.md`).
- **Стиль**: Строго придерживайтесь `cargo fmt`.
- **Производительность**: Используйте `Arc<T>` для разделяемого состояния, избегайте лишнего копирования данных.

## Рабочий процесс
1. **Анализ**: Перед внесением изменений изучите соответствующий крейт в `crates/`.
2. **Реализация**: Вносите изменения хирургически, соблюдая существующие паттерны.
3. **Проверка**:
   - `cargo build --workspace`
   - `cargo clippy --workspace --all-targets -- -D warnings`
   - `cargo test --workspace`
4. **Интеграция**: При изменении API всегда проверяйте, что изменения отражены в дашборде и SDK (JS/Python).

## Структура крейтов
- `openfang-kernel`: Центральный узел, управляющий всеми подсистемами.
- `openfang-runtime`: Логика выполнения агентов и инструментов.
- `openfang-api`: Определение маршрутов и серверная логика.
- `openfang-types`: Общие типы данных для всех крейтов.

## Полезные команды
- `cargo run -- doctor`: Проверка локальной среды.
- `cargo run -- start`: Запуск демона.
- `cargo test -p <crate_name>`: Запуск тестов для конкретного крейта.

Подробные инструкции по тестированию и архитектуре см. в `AGENTS.md`.
