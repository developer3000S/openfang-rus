## Спринт 1 — Критические исправления (3-4 дня)

Это критические проблемы. Без них приложение буквально падает или выглядит сломанным.

### 1.1 Исправление раздувания токенов (агенты падают после 3 сообщений) — ГОТОВО

**Статус: ЗАВЕРШЕНО** — Все 13 пунктов реализованы в compactor.rs, context_overflow.rs, context_budget.rs, agent_loop.rs, kernel.rs, agent.rs и prompt_builder.rs.

**Проблема (была):** Одно сообщение в чате потребляло около 45 000 входных токенов (определения инструментов + системный промпт). К третьему сообщению достигался лимит в 100 000, и приложение падало с ошибкой "Token quota exceeded".

**Что нужно сделать:**

1. **Добавить оценку токенов и защиту контекста** (`crates/openfang-runtime/src/compactor.rs`)
   - Добавить `estimate_token_count(messages, system_prompt, tools)` — эвристика chars/4.
   - Добавить `needs_compaction_by_tokens(estimated, context_window)` — срабатывает при 70% емкости.
   - Добавить `token_threshold_ratio: f64` (по умолчанию 0.7) и `context_window_tokens: usize` (по умолчанию 200 000) в `CompactionConfig`.
   - Снизить порог сообщений с 80 до 30.

2. **Добавить защиту токенов внутри цикла** (`crates/openfang-runtime/src/agent_loop.rs`)
   - Перед каждым вызовом LLM: оценивать количество токенов относительно окна контекста.
   - Свыше 70%: экстренная обрезка старых сообщений (оставить последние 10), запись предупреждения в лог.
   - Свыше 90%: агрессивная обрезка до последних 4 сообщений + вставка саммари (сводки).
   - Снизить `MAX_HISTORY_MESSAGES` с 40 до 20.
   - Снизить `MAX_TOOL_RESULT_CHARS` с 50 000 до 15 000.

3. **Фильтрация инструментов по профилю в ядре** (`crates/openfang-kernel/src/kernel.rs`)
   - В `available_tools()`: использовать `tool_profile` из манифеста для фильтрации.
   - Вызывать `tool_profile.tools()` для получения разрешенных имен инструментов, фильтровать `builtin_tool_definitions()`.
   - Отправлять ВСЕ инструменты только если профиль — `Full` И у агента есть возможность `ToolAll`.
   - Только это сокращает количество инструментов в чате по умолчанию с 41 до ~8 (экономит ~15-20 тыс. токенов).

4. **Увеличить квоту токенов по умолчанию** (`crates/openfang-types/src/agent.rs`)
   - Изменить `max_llm_tokens_per_hour` со 100 000 до 1 000 000.
   - 100 тыс. — это слишком мало, один системный промпт занимает 30-40 тыс. токенов.

5. **Триггер компакции на основе токенов** (`crates/openfang-kernel/src/kernel.rs`)
   - В `send_message_streaming()`: заменить проверку только по количеству сообщений на проверку с учетом токенов.
   - После компакции убедиться, что количество токенов действительно уменьшилось.

6. **Сжать вставки в системный промпт** (`crates/openfang-kernel/src/kernel.rs`)
   - Ограничить канонический контекст до 500 символов.
   - Ограничить контекст памяти до 3 элементов / по 200 символов каждый.
   - Ограничить знания о навыках (skill knowledge) до 2000 символов в сумме.
   - Пропускать саммари MCP, если количество инструментов < 3.

**Готово, когда:**
- `cargo test --workspace` проходит успешно.
- При запуске агента и отправке 10+ сообщений ошибка "Token quota exceeded" не возникает.
- Количество токенов первого сообщения снижается с ~45 тыс. до ~15-20 тыс.

**Что нужно сделать:**

2. Распарсить данные base64, создать запись в `/api/uploads/` (аналогично `image_generate`).
3. Сохранить `_imageUrls` в карточке инструмента.
4. Интерфейс уже отображает `tool._imageUrls` — нужно просто заполнить их.

**Файлы:** `crates/openfang-api/static/js/pages/chat.js`, `crates/openfang-runtime/src/tool_runner.rs`

**Готово, когда:**
- Скриншоты браузера отображаются как встроенные изображения в карточках инструментов.
- При клике изображение открывается в полном размере в новой вкладке.
