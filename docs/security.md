<a name="1-security-overview"></a>
## 1. Обзор безопасности

OpenFang реализует принцип **эшелонированной защиты** (defense-in-depth). Ни один механизм не считается единственным защитником; вместо этого 16 независимых систем образуют перекрывающиеся слои, так что сбой в одном слое перехватывается другими.

| # | Система | Крейт | От чего защищает |
|---|--------|-------|------------------|
| 1 | Безопасность на основе возможностей | `openfang-types` | Несанкционированные действия агентов |
| 2 | Двойной учет WASM | `openfang-runtime` | Бесконечные циклы, DoS процессора |
| 3 | Журнал аудита Меркла | `openfang-runtime` | Подделка логов аудита |
| 4 | Отслеживание пометок | `openfang-types` | Инъекции в промпты, утечка данных |
| 5 | Подпись манифестов Ed25519 | `openfang-types` | Атаки на цепочку поставок |
| 6 | Защита от SSRF | `openfang-runtime` | Server-Side Request Forgery |
| 7 | Обнуление секретов | `openfang-runtime`, `openfang-channels` | Анализ памяти, утечка ключей |
| 8 | Взаимная аутентификация OFP | `openfang-wire` | Несанкционированные подключения узлов |
| 9 | Заголовки безопасности | `openfang-api` | XSS, кликджекинг, MIME-сниффинг |
| 10 | Ограничитель GCRA | `openfang-api` | Злоупотребление API, отказ в обслуживании |
| 11 | Предотвращение Path Traversal | `openfang-runtime` | Атаки с обходом директорий |
| 12 | Песочница подпроцессов | `openfang-runtime` | Утечка секретов через дочерние процессы |

<a name="2-capability-based-security"></a>
## 2. Безопасность на основе возможностей

**Источник:** `openfang-types/src/capability.rs`

OpenFang использует безопасность на основе возможностей (capabilities). Агент может выполнять только те действия, на которые ему было явно дано разрешение. Возможности неизменны после создания агента и контролируются на уровне ядра.

### 2.1 Варианты возможностей

Перечисление `Capability` определяет каждый тип разрешения:

```rust
pub enum Capability {
    // Файловая система
    FileRead(String),       // Глоб-шаблон, например "/data/*"
    FileWrite(String),

    // Сеть
    NetConnect(String),     // Шаблон Host:port, например "*.openai.com:443"
    NetListen(u16),

    // Инструменты
    ToolInvoke(String),     // ID конкретного инструмента
    ToolAll,                // Все инструменты (опасно)

    // LLM
    LlmQuery(String),
    LlmMaxTokens(u64),

    // Взаимодействие агентов
    AgentSpawn,
    AgentMessage(String),
    AgentKill(String),

    // Память
    MemoryRead(String),
    MemoryWrite(String),

    // Shell
    ShellExec(String),
    EnvRead(String),

    // Протокол OFP
    OfpDiscover,
    OfpConnect(String),
    OfpAdvertise,

    // Экономика
    EconSpend(f64),
    EconEarn,
    EconTransfer(String),
}
```

### 2.2 Сопоставление по шаблону

Функция `capability_matches(granted, required)` реализует сопоставление в стиле glob:

- **Точное совпадение:** `"api.openai.com:443"` соответствует `"api.openai.com:443"`
- **Полная подстановка (wildcard):** `"*"` соответствует чему угодно
- **Префиксная подстановка:** `"*.openai.com:443"` соответствует `"api.openai.com:443"`
- **Числовые границы:** `LlmMaxTokens(10000)` разрешает `LlmMaxTokens(5000)` (дано >= запрошено)

### 2.3 Точка контроля

В песочнице WASM каждый вызов хоста проверяется **перед** выполнением функцией `check_capability()` в `host_functions.rs`:

```rust
fn check_capability(
    capabilities: &[Capability],
    required: &Capability,
) -> Result<(), serde_json::Value> {
    for granted in capabilities {
        if capability_matches(granted, required) {
            return Ok(());
        }
    }
    Err(json!({"error": format!("Capability denied: {required:?}")}))
}
```

### 2.4 Наследование возможностей

Когда агент создает дочернего агента, `validate_capability_inheritance()` гарантирует, что возможности ребенка являются **подмножеством** возможностей родителя. Это предотвращает эскалацию привилегий.

<a name="3-wasm-dual-metering"></a>
## 3. Двойной учет ресурсов WASM

**Источник:** `openfang-runtime/src/sandbox.rs`

Недоверенные модули WASM работают в песочнице Wasmtime с **двумя независимыми** механизмами учета, работающими одновременно.

### 3.1 Учет топлива (детерминированный)

Учет топлива (fuel) считает инструкции WASM. Движок вычитает топливо за каждую выполненную инструкцию. Когда бюджет исчерпан, выполнение прерывается с ошибкой `Trap::OutOfFuel`.

### 3.2 Прерывание по эпохам (реальное время)

Поток-сторож (watchdog) засыпает на заданный таймаут, затем увеличивает эпоху движка. Когда эпоха превышает дедлайн хранилища, выполнение прерывается с ошибкой `Trap::Interrupt`.

### 3.3 Зачем нужны оба?

| Свойство | Топливо (Fuel) | Эпохи (Epoch) |
|----------|------|-------|
| **Метрика** | Количество инструкций | Астрономическое время |
| **Точность** | Детерминировано, воспроизводимо | Недетерминировано |
| **Что ловит** | Интенсивные циклы ЦП | Блокировка вызовов хоста, ожидание ввода-вывода |

<a name="4-merkle-hash-chain-audit-trail"></a>
## 4. Журнал аудита на базе цепочки хешей Меркла

**Источник:** `openfang-runtime/src/audit.rs`

Каждое критически важное для безопасности действие добавляется в защищенную от несанкционированного доступа цепочку хешей Меркла. Каждая запись содержит хеш SHA-256 своего содержимого, объединенный с хешем предыдущей записи.

### 4.1 Структура записи

```rust
pub struct AuditEntry {
    pub seq: u64,          // Монотонно возрастающий номер
    pub timestamp: String, // ISO-8601
    pub agent_id: String,
    pub action: AuditAction,
    pub detail: String,    // напр. имя инструмента, путь к файлу
    pub outcome: String,   // "ok", "denied", сообщение об ошибке
    pub prev_hash: String, // SHA-256 предыдущей записи
    pub hash: String,      // SHA-256 текущей записи + prev_hash
}
```

### 4.2 Проверка целостности цепочки

`AuditLog::verify_integrity()` проходит по всей цепочке и пересчитывает каждый хеш. Если какая-либо запись была подделана, пересчитанный хеш не совпадет с сохраненным, или связь `prev_hash` будет нарушена.

<a name="5-information-flow-taint-tracking"></a>
## 5. Отслеживание пометок информационных потоков

**Источник:** `openfang-types/src/taint.rs`

OpenFang реализует модель распространения пометок (taint), которая предотвращает попадание помеченных (загрязненных) значений в чувствительные приемники (sinks) без явного снятия пометки (деклассификации). Это защищает от инъекций в промпты и утечки данных.

### 5.1 Метки загрязнения

```rust
pub enum TaintLabel {
    ExternalNetwork,  // Данные из внешних сетевых запросов
    UserInput,        // Прямой ввод пользователя
    Pii,              // Персональные данные
    Secret,           // API-ключи, токены, пароли
    UntrustedAgent,   // Данные от агентов в песочнице
}
```

### 5.2 Приемники пометок (Sinks)

`TaintSink` определяет, какие метки **заблокированы** для передачи в него:

| Приемник | Блокируемые метки | Обоснование |
|------|---------------|-----------|
| `TaintSink::shell_exec()` | `ExternalNetwork`, `UntrustedAgent`, `UserInput` | Предотвращение инъекции команд |
| `TaintSink::net_fetch()` | `Secret`, `Pii` | Предотвращение эксфильтрации данных |
| `TaintSink::agent_message()` | `Secret` | Предотвращение утечки секретов другим агентам |

<a name="6-ed25519-manifest-signing"></a>
## 6. Подпись манифестов Ed25519

**Источник:** `openfang-types/src/manifest_signing.rs`

Манифесты агентов определяют их возможности и инструменты. Скомпрометированный манифест может предоставить повышенные привилегии. Этот модуль обеспечивает криптографическую подпись на основе Ed25519.

- Изменение содержимого манифеста после подписания вызывает **несоответствие хеша**.
- Замена публичного ключа другим вызывает **ошибку проверки подписи**.

<a name="7-ssrf-protection"></a>
## 7. Защита от SSRF

**Источник:** `openfang-runtime/src/host_functions.rs`

Функция `host_net_fetch` включает комплексную защиту от Server-Side Request Forgery.

1. **Валидация схем:** Разрешены только `http://` и `https://`.
2. **Черный список имен хостов:** Блокируются `localhost`, эндпоинты метаданных облаков (AWS/GCP).
3. **Проверка после резолвинга DNS:** Функция разрешает имя хоста в IP-адреса и проверяет **каждый полученный IP** на принадлежность к приватным диапазонам. Это предотвращает атаки типа DNS rebinding.

---

<a name="8-secret-zeroization"></a>
## 8. Обнуление секретов

OpenFang использует `Zeroizing<String>` из крейта `zeroize` для каждого поля, содержащего секретные данные. Когда значение удаляется из памяти (drop), его область памяти перезаписывается нулями.

Это гарантирует, что секреты (API-ключи, токены) не останутся в памяти после использования, где они могли бы быть извлечены с помощью дампов памяти или инструментов криминалистического анализа.

---

<a name="9-ofp-mutual-authentication"></a>
## 9. Взаимная аутентификация OFP

**Источник:** `openfang-wire/src/peer.rs`

Сетевой протокол OpenFang (OFP) использует HMAC-SHA256 с взаимной аутентификацией на основе одноразовых чисел (nonce).

- **Взаимная аутентификация:** Обе стороны доказывают знание общего секрета.
- **Защита от воспроизведения:** Случайные UUID nonces для каждого рукопожатия.
- **Устойчивость к атакам по времени:** Использование `subtle::ConstantTimeEq` для сравнения HMAC.

<a name="10-security-headers"></a>
## 10. Заголовки безопасности

Промежуточное ПО (middleware) `security_headers` применяется ко **всем** ответам API:

| Заголовок | Значение | От чего защищает |
|--------|-------|------------------|
| `X-Content-Type-Options` | `nosniff` | MIME-сниффинг |
| `X-Frame-Options` | `DENY` | Кликджекинг через iframe |
| `X-XSS-Protection` | `1; mode=block` | Отраженный XSS |
| `Content-Security-Policy` | См. ниже | XSS, инъекция кода, утечка данных |
| `Cache-Control` | `no-store, ...` | Кэширование чувствительных данных |

<a name="11-gcra-rate-limiter"></a>
## 11. Ограничитель частоты GCRA

OpenFang использует алгоритм GCRA (Generic Cell Rate Algorithm) для ограничения частоты запросов к API с учетом "стоимости" операций.

- **Бюджет:** 500 токенов в минуту на один IP-адрес.
- **Стоимость операций:** Чтение здоровья — 1 токен, создание агента — 50 токенов, запуск воркфлоу — 100 токенов.

---

<a name="12-path-traversal-prevention"></a>
## 12. Предотвращение обхода путей (Path Traversal)

Реализовано два уровня защиты:
1. **Отказ от путей с компонентами `..`**.
2. **Канонизация путей** через `std::fs::canonicalize` перед выполнением операций.

Проверка на Path Traversal всегда выполняется **после** проверки прав доступа (capabilities), обеспечивая дополнительный слой защиты.

---

<a name="13-subprocess-sandbox"></a>
## 13. Песочница подпроцессов

При запуске дочерних процессов (например, инструментов shell) наследуемое окружение полностью очищается с помощью `cmd.env_clear()`. После этого возвращаются только безопасные переменные (напр. `PATH`, `LANG`) и те, что явно разрешены в конфигурации.

Это предотвращает случайную передачу секретов (напр. `OPENAI_API_KEY`) скриптам или внешним утилитам.

<a name="14-prompt-injection-scanner"></a>
## 14. Сканер инъекций в промпты

**Источник:** `openfang-skills/src/verify.rs`

`SkillVerifier` ищет опасные паттерны в текстах промптов навыков:
- Попытки игнорирования инструкций ("ignore previous instructions").
- Паттерны эксфильтрации данных ("send to http").
- Упоминания опасных команд shell ("rm -rf", "sudo").

---

<a name="15-loop-guard"></a>
## 15. Защита от циклов (Loop Guard)

Отслеживает вызовы инструментов в рамках одного цикла агента.
- **Предупреждение** при 3 идентичных вызовах (одинаковый инструмент + одинаковые параметры).
- **Блокировка** вызова при 5 повторениях.
- **Circuit Breaker:** полная остановка агента после 30 вызовов инструментов за одну итерацию.

---

<a name="16-session-repair"></a>
## 16. Восстановление сессий

Перед отправкой истории в LLM модуль исправляет структурные ошибки:
- Удаляет результаты инструментов без соответствующих вызовов.
- Объединяет идущие подряд сообщения от одной роли (требование Anthropic API).
- Удаляет пустые сообщения.

---

<a name="17-health-endpoint-redaction"></a>
## 17. Ограничение данных здоровья

- **Публичный эндпоинт (`/api/health`)**: Доступен без аутентификации, возвращает только `"status": "ok"`.
- **Подробный эндпоинт (`/api/health/detail`)**: Требует API-ключ, возвращает количество агентов, время работы и предупреждения конфига.

## Сводка модели угроз

| Угроза | Как нейтрализуется |
|--------|-------------|
| Несанкционированный доступ к файлам | Безопасность на основе возможностей (Capability-based) |
| Эскалация прав дочерним агентом | Валидация наследования возможностей |
| Бесконечный цикл в WASM навыке | Двойной учет: топливо + эпохи |
| Подделка логов аудита | Цепочка хешей Меркла |
| Инъекция в промпт через внешние данные | Отслеживание пометок (Taint tracking) |
| Утечка данных через LLM | Блокировка передачи Secret/Pii в сетевые инструменты |
| Поддельный манифест агента | Подпись Ed25519 |
| SSRF к облачным метаданным | Проверка IP + блокировка хостов + проверка DNS |
| Восстановление ключа из дампа памяти | Использование Zeroizing<String> |
| Подмена API / DoS | Ограничитель GCRA + Заголовки безопасности |
| Обход путей через `../` | safe_resolve_path / safe_resolve_parent |
| Вредоносные навыки | Сканер инъекций + контрольные суммы SHA256 |
